## v2.3.0 — June 2025

This release focuses on reliability and ecosystem integrations. Webhook delivery is now significantly more robust, bulk data operations are available via the API, and a native Slack integration brings Google activity directly into your channels.

### New Features

**Webhook retry logic with delivery guarantees**
Webhooks now retry failed deliveries automatically on an exponential backoff schedule (1 min → 5 min → 30 min → 2 hrs → 8 hrs), giving your endpoints time to recover from transient failures. Each delivery attempt is logged with its HTTP status code, response time, and response body. You can inspect the full delivery history in **Settings → Webhooks → Logs** and manually re-trigger any failed delivery. See [Webhooks](/code/api/webhooks) for the updated payload schema and the new `X-Google-Delivery-Id` header.

**Bulk export endpoint (`POST /v2/exports`)**
A new asynchronous bulk export endpoint lets you programmatically export any subset of your workspace data without going through the UI. Specify the resource types, date ranges, and output format (JSON or CSV) in the request body. The API returns a job ID you can poll for completion, and a pre-signed download URL valid for 48 hours once the export is ready. Rate-limited to 5 concurrent export jobs per workspace. See [API Endpoints](/code/api/endpoints) for the full parameter reference.

**Native Slack integration**
Connect Google to your Slack workspace in **Settings → Integrations → Slack**. Once connected, you can configure per-channel notifications for events including document publishes, failed webhook deliveries, new team member invitations, and API key expiry warnings. Messages include direct links back to the relevant resource in Google. See [Integrations](/guides/integrations) for setup instructions.

### Improvements

- **Webhook signature verification** now uses HMAC-SHA256 with a rotating secret, replacing the previous static token approach. Existing webhooks continue to work with the legacy token until 1 September 2025, when legacy verification is removed.
- **API key creation flow** now surfaces the generated key value only once and prompts you to copy it before closing the modal, reducing the risk of lost keys.
- The **Trash** view in Data Management now supports bulk-restore and bulk-permanent-delete operations, with a confirmation dialog for permanent deletions.
- Search indexing latency for newly published documents reduced from ~30 seconds to ~5 seconds.

### Bug Fixes

- Fixed an issue where webhook test deliveries did not honour the workspace's IP allowlist.
- Fixed a race condition that occasionally caused duplicate `document.created` events to be fired when documents were saved in quick succession.
- Fixed incorrect `X-RateLimit-Reset` timestamps being returned in UTC+0 instead of Unix epoch time.
- Fixed a UI bug where the **Billing** page showed an incorrect next renewal date for annual plans.
- Fixed an edge case where transferring workspace ownership failed silently if the new owner had a pending email verification.

## v2.2.0 — April 2025

This release brings the Environments feature to general availability, a significantly upgraded search experience, and expanded OAuth scope granularity for fine-grained access control.

### New Features

**Environments — now generally available**
Environments allow you to maintain separate configurations (API keys, integrations, webhook endpoints, and settings) for `development`, `staging`, and `production` within a single workspace. Switch between environments from the top navigation bar. Resources created in one environment are isolated from others by default; you can promote a configuration from `staging` to `production` with a single click. Previously in beta, Environments is now available on all Starter, Pro, and Enterprise plans. See [Environment Configuration](/configuration/environment) for a full guide.

**Improved full-text search**
The search engine has been rebuilt on a new indexing pipeline with the following improvements: typo tolerance (up to 2 edit distance), phrase-match boosting for quoted queries, field-scoped search (e.g. `title:"onboarding" tag:api`), and result highlighting. Search now also surfaces API endpoint documentation, code snippets, and changelog entries in addition to knowledge base documents.

**Granular OAuth scopes**
OAuth applications can now request scopes at the resource level, such as `read:documents`, `write:documents`, and `delete:documents`, instead of the previous coarse-grained `documents` scope. Existing OAuth tokens are automatically mapped to the new scope model and remain valid. New authorization flows will prompt users with the updated, more descriptive consent screen. See [API Authentication](/code/api/authentication) for the full scope reference.

### Improvements

- **Integration health dashboard** added to **Settings → Integrations**, showing the last successful sync timestamp, error rate, and a quick-reconnect button for each connected integration.
- The **Activity Log** now includes filter controls for event type, actor (user or API key), and date range, and supports CSV export.
- API error responses now include a `docs_url` field pointing to the relevant documentation page for the error code, making it easier to self-serve fixes.
- Dashboard loading time reduced by approximately 40% through lazy-loading of workspace statistics panels.

### Bug Fixes

- Fixed an issue where environment-specific API keys were occasionally visible across environments in the Settings UI.
- Fixed OAuth token refresh failing silently when the refresh token was near expiry.
- Fixed search returning stale results for documents updated within the previous 60 seconds.
- Fixed a bug where the **Remove Integration** button was visible to Member-role users (it is Admin-only and now correctly hidden).
- Fixed incorrect pagination cursors being returned for list endpoints when a `filter` parameter was combined with `sort=updated_at`.

## v2.1.0 — February 2025

This release delivers the most-requested community features: CSV data import, a completely rebuilt roles and permissions system, and standardised rate-limit headers across all API endpoints.

### New Features

**CSV import**
You can now import documents and knowledge base entries directly from CSV files via **Data Management → Import**. The importer supports field mapping (drag columns to the appropriate target field), validation with row-level error reporting, and a dry-run mode that shows a preview of what would be created without writing any data. Supports files up to 50 MB / 500,000 rows. A downloadable import template is available in the import dialog. See [Data Management](/guides/data-management) for the complete guide.

**Roles & permissions overhaul**
The team permissions system has been rebuilt from scratch. The previous binary Owner/Member model is replaced with a flexible role system: **Owner**, **Admin**, **Member**, and **Viewer**. Enterprise plans gain access to **Custom Roles**, allowing Admins to create roles with any combination of the 40+ available permissions. Existing workspaces are migrated automatically: previous Members become Members, and previous Owners become Owners with an Admin role also available. See [Permissions](/configuration/permissions) for the full role comparison matrix.

**Rate-limit response headers**
All API responses now include three standard rate-limit headers to help integrations manage throughput proactively:

```http title="Rate-limit headers on every API response"
X-RateLimit-Limit: 1000
X-RateLimit-Remaining: 847
X-RateLimit-Reset: 1719859200
```

`X-RateLimit-Reset` is a Unix timestamp indicating when the current window resets. See [Rate Limits](/code/advanced/rate-limits) for details.

### Improvements

- **Audit log retention** extended from 30 days to 90 days on Pro plans and 1 year on Enterprise plans.
- The **API Keys** settings page now shows the last-used timestamp and the approximate geographic region of the last request for each key, aiding in anomaly detection.
- Document editor autosave interval reduced from 30 seconds to 10 seconds, reducing potential data loss on unexpected disconnections.
- Improved validation messages on the team invite flow to clearly distinguish between "email already in workspace" and "email already has a pending invite".

### Bug Fixes

- Fixed CSV exports containing non-ASCII characters being corrupted when opened in Microsoft Excel (switched to UTF-8 with BOM for Excel compatibility).
- Fixed a permissions bug where Members could view billing information if they navigated directly to the URL.
- Fixed the document list view not reflecting real-time updates when another user archived a document in the same session.
- Fixed 500 errors being returned instead of 422 when malformed JSON was sent to `POST` endpoints.
- Fixed Member-role users being able to delete their own API keys even when workspace policy had key management restricted to Admins.

## v2.0.0 — December 2024

The v2.0 release is a major milestone — a complete rebuild of the API, a new dashboard experience, and a rewritten SDK. If you are migrating from v1, follow the [migration guide](/code/advanced/versioning) to update your integrations before the v1 deprecation date of 30 June 2025.

### New Features

**API v2 — complete relaunch**
The Google API has been redesigned from the ground up with REST best practices, consistent resource naming, cursor-based pagination on all list endpoints, structured error objects with machine-readable `error_code` values, and full OpenAPI 3.1 specification. All endpoints now live under the `/v2/` prefix. Key changes from v1 include:

- Authentication moves from query-parameter API keys to `Authorization: Bearer` headers.
- All timestamps use ISO 8601 format (`2024-12-01T10:30:00Z`) instead of Unix integers.
- Bulk operations are first-class, with new `POST /v2/*/bulk-create` and `DELETE /v2/*/bulk-delete` endpoints.
- Webhooks are now event-driven with a structured `event` envelope rather than per-resource callbacks.

See [API Endpoints](/code/api/endpoints) and [API Errors](/code/api/errors) for the full reference.

**New dashboard**
The Google dashboard has been redesigned with a focus on fast navigation and at-a-glance workspace health. Highlights include a collapsible sidebar with keyboard navigation, a global command palette (`⌘K` / `Ctrl+K`), a workspace activity feed on the home screen, and a redesigned Settings area with grouped sections. The dashboard is built on a new frontend stack and delivers a 60% improvement in time-to-interactive on first load.

**SDK v2**
The official Google SDK has been rewritten to target the v2 API. SDK v2 ships as an ES module with full TypeScript support, tree-shakeable exports, built-in retry logic with exponential backoff, and request/response interceptors. Install the new version with `npm install @google/sdk@2`. See [SDK Installation](/code/sdk/installation) and [SDK Usage](/code/sdk/usage) for the updated quick-start guide.

### Improvements

- **Documentation site** (you're reading it) rebuilt with improved search, versioned API reference, and in-page code examples for every endpoint.
- API response times improved by 35% on average due to database query optimisation and connection pooling changes rolled out alongside the v2 launch.
- Workspace creation wizard reduced from 7 steps to 3, with sensible defaults for all optional settings.

### Bug Fixes

- Resolved a long-standing issue where deleting a knowledge base entry that was referenced by a webhook subscription caused a 500 error on subsequent webhook deliveries.
- Fixed API key rotation not invalidating the old key immediately in all geographic regions (was taking up to 5 minutes in some cases).
- Fixed the dashboard showing incorrect member counts for workspaces with pending invites.
- Corrected a data serialisation bug that caused boolean fields to be returned as `0`/`1` integers instead of `true`/`false` in list endpoint responses.

<Note>
  API v1 is deprecated as of this release and will reach end-of-life on **30 June 2025**. All v1 endpoints will return `410 Gone` after that date. Follow the [versioning and migration guide](/code/advanced/versioning) to upgrade your integrations.
</Note>

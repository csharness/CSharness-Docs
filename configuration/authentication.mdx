Every request to the Google API must be authenticated. Google supports two authentication methods: **API key authentication** for server-to-server integrations and scripts, and **OAuth 2.0** for user-level access where your application acts on behalf of a specific Google user. Choose the method that fits your use case — both methods use the same `Authorization` header format.

## How API Key Authentication Works

API key authentication is the simplest way to access the Google API. You generate a key from your workspace settings, then include it as a Bearer token in the `Authorization` header of every request. The API validates the key, checks its scope and expiry, and either fulfills or rejects the request.

```http title="Authorization header format"
Authorization: Bearer YOUR_API_KEY
```

API keys are scoped to specific resources and actions. A key with `read:docs` scope can read documents but cannot create or delete them. Always use the narrowest scope your integration requires.

<Note>
  Never embed API keys in client-side code, browser JavaScript, or public repositories. If a key is exposed, rotate it immediately — see [Rotating and Revoking Keys](#rotating-and-revoking-keys) below.
</Note>

## Generating an API Key

You can create multiple API keys with different names, scopes, and expiry dates. This makes it easy to issue a separate key for each integration and revoke individual keys without disrupting others.

<Steps>
  <Step title="Open API Keys settings">
    Navigate to **Settings → API Keys** in the left sidebar. You see a list of all existing keys, their scopes, and expiry dates.
  </Step>
  <Step title="Create a new key">
    Click **New Key**. A dialog opens with the following fields:

    - **Name** — A descriptive label (e.g., `ci-pipeline-key`, `zapier-integration`). This is for your reference only.
    - **Expiry** — Choose a duration: 30 days, 90 days, 1 year, or No Expiry. We recommend setting an expiry for all keys.
    - **Scope** — Select one or more permission scopes from the list. See the scope reference below.
  </Step>
  <Step title="Copy and store the key">
    Click **Create Key**. The key is displayed **once** — copy it immediately and store it in a secrets manager or environment variable. Google does not store the raw key value and cannot show it again.
  </Step>
</Steps>

### Available Scopes

| Scope | Access granted |
|---|---|
| `read:docs` | Read documents and pages |
| `write:docs` | Create and update documents and pages |
| `delete:docs` | Delete documents and pages |
| `read:members` | List workspace members and roles |
| `write:members` | Invite and remove members |
| `read:settings` | Read workspace settings |
| `write:settings` | Update workspace settings |
| `full` | All permissions (use with caution) |

## Rotating and Revoking Keys

Rotate a key to generate a new value while briefly keeping the old one active during the transition. Revoke a key to invalidate it immediately.

<Tabs>
  <Tab title="Rotate a Key">
    <Steps>
      <Step title="Find the key">
        Go to **Settings → API Keys** and locate the key you want to rotate.
      </Step>
      <Step title="Initiate rotation">
        Click the **⋯** menu next to the key and select **Rotate**. Google generates a new key value and gives you a **24-hour overlap window** during which both the old and new key are valid.
      </Step>
      <Step title="Update your integration">
        Replace the old key in your environment or secrets manager with the new value. Once updated, the old key is automatically invalidated after the overlap window closes.
      </Step>
    </Steps>
  </Tab>
  <Tab title="Revoke a Key">
    <Steps>
      <Step title="Find the key">
        Go to **Settings → API Keys** and locate the key you want to revoke.
      </Step>
      <Step title="Revoke immediately">
        Click the **⋯** menu and select **Revoke**. Confirm in the dialog. The key is invalidated instantly — all requests using it return `401 Unauthorized`.
      </Step>
    </Steps>

    <Warning>
      Revoking a key is immediate and cannot be undone. Any integration using the revoked key stops working instantly. Make sure you have a replacement key deployed before revoking.
    </Warning>
  </Tab>
</Tabs>

## OAuth 2.0 for User-Level Access

Use OAuth 2.0 when your application needs to act on behalf of a specific Google user — for example, a third-party app that reads a user's documents with their consent. OAuth tokens are tied to the user who authorized them and respect that user's role and permissions.

### Step 1 — Register Your OAuth Application

Go to **Settings → Developer → OAuth Apps** and click **New OAuth App**. Provide:

- **App name** and **description** — shown to users on the consent screen.
- **Redirect URI** — the URL Google redirects to after the user approves authorization (e.g., `https://yourapp.com/oauth/callback`).

After saving, Google issues a **Client ID** and **Client Secret**. Store the Client Secret securely — treat it like a password.

### Step 2 — Redirect Users to the Authorization URL

Send users to the Google authorization endpoint:

```http title="Authorization URL"
GET https://api.google.com/oauth/authorize
  ?client_id=YOUR_CLIENT_ID
  &redirect_uri=https://yourapp.com/oauth/callback
  &response_type=code
  &scope=read:docs write:docs
  &state=RANDOM_STATE_STRING
```

Include a `state` parameter to protect against CSRF attacks. When the user approves, Google redirects to your `redirect_uri` with a short-lived `code` parameter.

### Step 3 — Exchange the Code for Tokens

Exchange the authorization code for an access token and refresh token:

```bash title="Token exchange"
curl -X POST https://api.google.com/oauth/token \
  -H "Content-Type: application/json" \
  -d '{
    "grant_type": "authorization_code",
    "client_id": "YOUR_CLIENT_ID",
    "client_secret": "YOUR_CLIENT_SECRET",
    "redirect_uri": "https://yourapp.com/oauth/callback",
    "code": "AUTHORIZATION_CODE"
  }'
```

The response includes:

```json title="Token response"
{
  "access_token": "eyJhbGci...",
  "token_type": "Bearer",
  "expires_in": 3600,
  "refresh_token": "dGhpcyBp..."
}
```

### Step 4 — Refresh an Expired Token

Access tokens expire after 1 hour. Use the refresh token to obtain a new access token without requiring the user to re-authorize:

```bash title="Token refresh"
curl -X POST https://api.google.com/oauth/token \
  -H "Content-Type: application/json" \
  -d '{
    "grant_type": "refresh_token",
    "client_id": "YOUR_CLIENT_ID",
    "client_secret": "YOUR_CLIENT_SECRET",
    "refresh_token": "dGhpcyBp..."
  }'
```

## Passing Credentials in Requests

Both API keys and OAuth access tokens are passed in the same `Authorization` header. The format is identical — `Bearer` followed by the token value.

<CodeGroup>
```bash title="API key — curl"
curl https://api.google.com/v1/docs \
  -H "Authorization: Bearer YOUR_API_KEY"
```

```bash title="OAuth token — curl"
curl https://api.google.com/v1/docs \
  -H "Authorization: Bearer YOUR_OAUTH_ACCESS_TOKEN"
```

```javascript title="API key — JavaScript fetch"
const response = await fetch('https://api.google.com/v1/docs', {
  headers: {
    'Authorization': `Bearer ${process.env.GOOGLE_API_KEY}`
  }
});
```

```python title="API key — Python requests"
import os, requests

response = requests.get(
    'https://api.google.com/v1/docs',
    headers={'Authorization': f'Bearer {os.environ["GOOGLE_API_KEY"]}'}
)
```
</CodeGroup>

## Authentication Error Responses

When authentication fails, Google returns a standard error response. Use the status code and error code to diagnose the issue.

| HTTP status | Error code | Cause |
|---|---|---|
| `401 Unauthorized` | `invalid_token` | The API key or token is malformed or does not exist |
| `401 Unauthorized` | `token_expired` | The API key has passed its expiry date, or the OAuth access token has expired |
| `403 Forbidden` | `insufficient_scope` | The key or token does not have the required scope for the requested action |
| `403 Forbidden` | `workspace_suspended` | Your workspace has been suspended — contact support |

```json title="Example 401 response"
{
  "error": "token_expired",
  "message": "The provided token has expired. Generate a new API key or refresh your OAuth token.",
  "status": 401
}
```

<Tip>
  If you receive a `403 insufficient_scope` error, check the scopes assigned to your API key in **Settings → API Keys**. You may need to generate a new key with broader scope or request additional OAuth scopes during the authorization flow.
</Tip>

For a full reference of API error codes, see [API Errors](/code/api/errors).

The Google REST API follows standard HTTP conventions. All endpoints are served over HTTPS from the base URL `https://api.google.example`. Request bodies must be JSON with `Content-Type: application/json`, and every response is JSON. Authenticate each request with an API key or OAuth 2.0 access token as described in the [Authentication guide](/code/api/authentication).

<Note>
  All endpoints are versioned under `/v1`. When a breaking change is introduced, a new version prefix (`/v2`, and so on) is released. See the [Versioning guide](/code/advanced/versioning) for the full policy.
</Note>

## Resources

Resources are the core content objects in Google. Each resource belongs to a project and can hold structured fields defined by your schema.

### List resources

Retrieve a paginated list of resources in a project.

**`GET /v1/resources`**

<ParamField query="project_id" type="string" required>
  The ID of the project to list resources from.
</ParamField>

<ParamField query="filter" type="string">
  A filter expression, for example `type:article status:published`. Multiple filters are ANDed.
</ParamField>

<ParamField query="sort" type="string">
  Field and direction, for example `created_at:desc` or `name:asc`. Defaults to `created_at:desc`.
</ParamField>

<ParamField query="limit" type="integer">
  Number of results per page. Minimum `1`, maximum `100`. Defaults to `20`.
</ParamField>

<ParamField query="cursor" type="string">
  Pagination cursor from the previous response's `next_cursor` field.
</ParamField>

<CodeGroup>
```bash title="Request"
curl -X GET "https://api.google.example/v1/resources?project_id=proj_abc&limit=2&sort=created_at:desc" \
  -H "Authorization: Bearer YOUR_API_KEY"
```

```json title="Response"
{
  "data": [
    {
      "id": "res_01hx",
      "name": "Getting Started Guide",
      "type": "article",
      "project_id": "proj_abc",
      "created_at": "2024-05-10T12:00:00Z",
      "updated_at": "2024-05-11T08:30:00Z"
    },
    {
      "id": "res_01hw",
      "name": "API Overview",
      "type": "article",
      "project_id": "proj_abc",
      "created_at": "2024-05-09T09:00:00Z",
      "updated_at": "2024-05-09T09:00:00Z"
    }
  ],
  "next_cursor": "eyJpZCI6InJlc18wMWh3In0",
  "total": 48
}
```
</CodeGroup>

### Create a resource

Create a new resource inside a project.

**`POST /v1/resources`**

<ParamField body="name" type="string" required>
  Human-readable name for the resource. Maximum 255 characters.
</ParamField>

<ParamField body="type" type="string" required>
  Resource type slug defined in your schema, for example `article` or `api-endpoint`.
</ParamField>

<ParamField body="project_id" type="string" required>
  ID of the project the resource belongs to.
</ParamField>

<ParamField body="fields" type="object">
  Key-value map of field values that conform to the project's schema definition.
</ParamField>

<CodeGroup>
```bash title="Request"
curl -X POST https://api.google.example/v1/resources \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Authentication Guide",
    "type": "article",
    "project_id": "proj_abc",
    "fields": {
      "status": "draft",
      "author": "Jane Doe"
    }
  }'
```

```json title="Response — 201 Created"
{
  "id": "res_01hy",
  "name": "Authentication Guide",
  "type": "article",
  "project_id": "proj_abc",
  "fields": {
    "status": "draft",
    "author": "Jane Doe"
  },
  "created_at": "2024-05-12T14:22:00Z",
  "updated_at": "2024-05-12T14:22:00Z"
}
```
</CodeGroup>

### Update a resource

Partially update a resource. Only fields included in the request body are modified.

**`PATCH /v1/resources/:id`**

<ParamField path="id" type="string" required>
  The unique ID of the resource to update.
</ParamField>

<ParamField body="name" type="string">
  New name for the resource.
</ParamField>

<ParamField body="fields" type="object">
  Partial field updates. Only supplied keys are overwritten.
</ParamField>

<CodeGroup>
```bash title="Request"
curl -X PATCH https://api.google.example/v1/resources/res_01hy \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"fields": {"status": "published"}}'
```

```json title="Response"
{
  "id": "res_01hy",
  "name": "Authentication Guide",
  "type": "article",
  "project_id": "proj_abc",
  "fields": {
    "status": "published",
    "author": "Jane Doe"
  },
  "created_at": "2024-05-12T14:22:00Z",
  "updated_at": "2024-05-12T15:00:00Z"
}
```
</CodeGroup>

### Delete a resource

Permanently delete a resource. This action cannot be undone.

**`DELETE /v1/resources/:id`**

<ParamField path="id" type="string" required>
  The unique ID of the resource to delete.
</ParamField>

<CodeGroup>
```bash title="Request"
curl -X DELETE https://api.google.example/v1/resources/res_01hy \
  -H "Authorization: Bearer YOUR_API_KEY"
```

```json title="Response — 204 No Content"
{}
```
</CodeGroup>

<Warning>
  Deleting a resource also removes all versions, comments, and associated metadata. There is no soft-delete or recycle bin for resources deleted via the API.
</Warning>

## Projects

Projects group related resources and define the schema that resources within them must follow.

### List projects

Retrieve all projects in your workspace.

**`GET /v1/projects`**

<CodeGroup>

### Delete a project

Permanently delete a project and all of its resources.

**`DELETE /v1/projects/:id`**

<ParamField path="id" type="string" required>
  The unique ID of the project to delete.
</ParamField>

<CodeGroup>
```bash title="Request"
curl -X DELETE https://api.google.example/v1/projects/proj_ghi \
  -H "Authorization: Bearer YOUR_API_KEY"
```

```json title="Response — 204 No Content"
{}
```
</CodeGroup>

<Warning>

</Warning>

## Workspace

Workspace endpoints let you read and update the top-level workspace that contains all your projects and members.

### Get workspace details

Retrieve details about your workspace.

**`GET /v1/workspace`**

<CodeGroup>
```bash title="Request"
curl -X GET https://api.google.example/v1/workspace \
  -H "Authorization: Bearer YOUR_API_KEY"
```

```json title="Response"
{
  "id": "ws_xyz",
  "name": "Acme Corp",
  "slug": "acme-corp",
  "plan": "pro",
  "member_count": 12,
  "project_count": 5,
  "created_at": "2023-11-01T09:00:00Z"
}
```
</CodeGroup>

---

### Update workspace settings

Update mutable properties of your workspace.

**`PATCH /v1/workspace`**

<ParamField body="name" type="string">
  New display name for the workspace. Maximum 100 characters.
</ParamField>

<ParamField body="slug" type="string">
  New URL slug. Must be lowercase alphanumeric with hyphens. Changing the slug updates all shareable URLs.
</ParamField>

<ParamField body="settings" type="object">
  Workspace-level settings object. See [Configuration → Settings](/configuration/settings) for available keys.
</ParamField>

<CodeGroup>
```bash title="Request"
curl -X PATCH https://api.google.example/v1/workspace \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name": "Acme Corporation", "settings": {"default_visibility": "private"}}'
```

```json title="Response"
{
  "id": "ws_xyz",
  "name": "Acme Corporation",
  "slug": "acme-corp",
  "plan": "pro",
  "member_count": 12,
  "project_count": 5,
  "created_at": "2023-11-01T09:00:00Z",
  "updated_at": "2024-05-12T17:00:00Z"
}
```
</CodeGroup>

<Tip>
  You need the `admin` OAuth scope (or an API key with admin privileges) to update workspace settings. Requests from lower-privileged tokens return `403 insufficient_scope`.
</Tip>
